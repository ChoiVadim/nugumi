# Lessons

- When building onboarding or setup UI, include a repeatable entry point before calling it done. A permission window that only appears on first-run is hard to QA and prevents users from reviewing instructions later.
- Keep first-run setup mode separate from manual review mode. If a setup window can be reopened after everything is complete, its primary CTA must have an explicit complete-state action like closing the window instead of recomputing the setup path.
- Status indicators in onboarding cards must not look like clickable buttons. Use quiet labels or icons for states like done/later; reserve filled capsules for real actions only.
- Permission setup is not enough for onboarding. New users also need a short product tour that explains the core actions, the exact clicks or shortcuts, and shows the same feature media used on the landing page.
- In feature onboarding, teach the primary gesture first. For Gizmate translate/rewrite, left-click and right-click are more important than keyboard shortcuts; shortcuts should be secondary fallback copy.
- In-app UI must load brand assets (logo/icon) from `Bundle.module` resources, not `NSApp.applicationIconImage`. The latter is the generic placeholder under `swift run` (no bundled icon), so the icon looks broken during development. Put a `logo.png` in `Sources/Gizmate/Resources` and load it via `Bundle.module.url(forResource:withExtension:)` so it renders identically in dev and in the packaged `.app`.
- When laying out a fixed-width sidebar header with a wide pixel font (Pixelify) plus a trailing badge, give the badge `.fixedSize()` and size the wordmark to the available width — `minimumScaleFactor` truncates the wordmark to "…" and a too-wide wordmark clips the badge off the column edge.
- For a "liquid glass + solid panel" window look, use a transparent `NSWindow` (`isOpaque=false`, `backgroundColor=.clear`, `appearance=.darkAqua`) with an `NSVisualEffectView` (`.hudWindow`, `.behindWindow`) as `contentView` hosting the SwiftUI view, and lay out content with a custom `HStack` — not `NavigationSplitView`, which imposes its own column backgrounds you can't fully clear. Clear SwiftUI areas show the glass; an opaque near-black `Color` makes the solid container.
- `AXIsProcessTrustedWithOptions(prompt:true)` is a permanent silent no-op once the app is already in the Accessibility list. Our launch-time `requestAccessibilityPermissionIfNeeded()` registers the row via `prompt:false`, so any later point-of-use `prompt:true` will NEVER show macOS's native dialog. For an at-use Accessibility request, open the pane directly (`x-apple.systempreferences:com.apple.preference.security?Privacy_Accessibility`) — that's the only reliably-visible UI.
- macOS's TCC "Quit & Reopen" (shown when you toggle Screen Recording for a running app) does NOT reliably relaunch `LSUIElement` agent apps — it quits but doesn't reopen; duplicate registered copies of the bundle id make it worse. Don't depend on it. Relaunch from inside the app: detach `sh -c 'sleep 1; open "<Bundle.main.bundlePath>"'` then `NSApp.terminate`, gated on `isRunningFromAppBundle`.
- Selection-to-result has TWO independent entry points and a point-of-use permission fix must cover BOTH: (1) the Carbon global hotkey `startSelectionTranslateOrReply`/`startSelectedTextTranslationForReplacement` (fires without Accessibility) and (2) the global mouse monitor `handleMouseUp` (also fires without AX, but used to `guard accessibilityIsTrusted() else { return }` — silently dead). The mouse drag-select is the PRIMARY UX, so fixing only the hotkey leaves "select text → nothing happens". Gate the at-use prompt on `isLikelySelectionGesture` + a time throttle so you don't reopen System Settings on every click. The Cmd+A path (`handleSelectAll`) does NOT need a fix — its keyboard monitor requires AX to deliver events, so it can't run (or prompt) without AX anyway.
- Screen Recording / Accessibility behavior can only be verified on the packaged `.app` (TCC is keyed to code identity + needs a real bundle). The `swift run`/`.build` dev binary can't be relaunched by macOS and its TCC prompts attach to a throwaway identity — a successful `swift build` only proves it compiles, not that the permission UX works.
- Test inputs must break the symmetry of the transform under test. All five original stroke-compositing test strokes sat on the vertical center of the frame, so a y-axis-flip regression in the coordinate mapping would have passed every test; one asymmetric-y stroke (top vs mirrored bottom pixel) closed the gap. When testing any coordinate mapping, pick sample points that distinguish the mapping from its plausible wrong variants (flip, offset, swap).
- Overriding an NSWindow property setter with an empty `set {}` to "freeze" a value is a trap: the getter lies while the window server keeps whatever state it had (for `sharingType`, the capturable default). Clamp instead by delegating: `set { super.sharingType = .none }` — the super call is what actually pushes the value to the window server.
- Never ask an LLM to put multi-line markdown inside a JSON string field — the two formats fight and you get either flattened text (strict JSON) or broken JSON (good markdown, model "escapes" the envelope and machine data leaks into the visible answer). Separate the channels: human text as plain markdown, machine data as one trailing fenced block with a distinctive info string, stripped deterministically by the parser even when its JSON is broken. Keep the old JSON path as a silent fallback for stubborn models.
- Liquid Glass (`NSGlassEffectView` in an `NSGlassEffectContainerView`) renders its SHAPE from the model frame, not the presentation layer: `animator().frame` teleports the glass to the destination on the first frame while the view's content animates. Consequence: glass-backed views cannot be flown anywhere on close — even flying all discs to one coincident center rect pops a full-opacity disc there instantly (partial travel is worse: a lumpy multi-circle blob). The only clean exit is a dissolve with untouched frames — a window-level alpha fade of the whole panel. Verified frame-by-frame from a screen recording via AVAssetImageGenerator.
- When an animation looks wrong only in one presentation context, diff the CONTEXTS before touching the shared animation (frame-by-frame video via AVAssetImageGenerator beats guessing). The quick-menu "mess" was the center ✕ living inside the ring panel's glass group; the fix was moving it to its own window (like the floating-bar presenter), not retuning the shared collapse — three rounds of animation tweaks were fixing the wrong variable.
- When the user explicitly prioritizes making an agentic feature work before release hardening, do not use incomplete production gates to block the developer-preview implementation. Separate the two tracks clearly: build the smallest feature-flagged agent loop now, keep dangerous capabilities constrained, and retain architecture, signing, cross-platform, and resource-limit gaps as release blockers rather than feature-development blockers.
- When the user gives concrete UI screenshots and asks for direct, local changes, keep planning proportional: confirm only a genuinely ambiguous interaction, then implement. Do not turn a small UI cleanup into a long planning workflow or create heavy planning artifacts unless the user explicitly asks for that process.
- When the user asks to remove a workflow plugin, uninstall it completely and stop invoking its tools, hooks, agents, and generated artifacts.
- For an experimental agent feature, prove one user-visible vertical first: request -> generated script -> sandbox failure -> agent repair -> passing tool. Do not expand into large OMO review trees, packaging, and release hardening before this flow is connected to the real UI; those checks come after the feature works end to end.
- Do not put a one-shot LLM router in front of Gizmate's tool agent. Pi must own the full generation session: choose prompt/native/Python, submit a typed candidate, request type-specific host validation, repair failures, and finish only the attested result. Python uses the sandbox; native actions are checked without executing their side effects.
- When Create moves to an agent loop, audit Edit and Fix in the same pass. Leaving legacy one-shot revise/repair calls produces two different reliability models inside one feature; all three actions must share the same Pi build-test-repair-attest path.
- A tool-building agent needs a real clarification channel, not only better generation prompts. Keep one visible chat transcript, let the same Pi session ask bounded `ask_user` questions, show only safe host-authored activity, and never persist or assign a generated candidate until the user explicitly presses Save.
- Once New Tool becomes a chat, remove leftover form chrome from that path. Put Send inside the composer, use the existing close button instead of a duplicate Cancel, and surface Save contextually inside the agent's ready message rather than in a permanent footer.
- When Create and Edit share an agent chat, delete the old edit form in the same change. Activity, clarification, errors, and the ready-to-save card must use one transcript in both modes; exact fields and script testing belong in Details.
- A strict agent protocol should stay strict at its boundary, but the model bridge may canonicalize one harmless presentation wrapper such as a single JSON code fence before validation. Never loosen candidate keys or accept prose around the action just to hide a format failure.
- Chat composers need explicit keyboard semantics: Return sends, Shift+Return remains with the multiline editor, and no second keyboard shortcut may trigger a duplicate send.
- Never give a chat composer placeholder `maxHeight: .infinity` inside a `ZStack`: it stretches the background while the real editor remains small, so most of the visible box is not clickable. Size the `TextEditor` itself and overlay the placeholder and Send button on that exact hit target.
- Do not call Gizmate's agentic tool builder broadly working while its verifier still rejects the exact high-value class the user is testing: Python tools with network access and dependencies. A friendly `UNSUPPORTED` response is not completion. Prove one real downloader path end to end — declared dependency, controlled network validation, repair loop, candidate Save, and saved-tool execution — before claiming arbitrary script generation.
- Before declaring a tool request unsupported, trace the real runner contract. Native `openURL` already supports an `{input}` template, so a selected link can be opened directly; the agent prompt must describe existing capabilities accurately and must not reward speculative refusal.
